# Harness assumptions the 2026-10-13 decompilation run broke

Haiku 5.5 workers did matching decompilation: C source that gcc 13.3 at `-O2` compiles to
the same code bytes as every function of two targets' objects. One suite per translation
unit, one test per function, three stages (`compile`, `missing`, `match`), a diff category
in the reason and a byte-match fraction (`frac`) per test. Targets: Ali Rudi's neat* troff
suite and C compiler (obscure, 1,070 functions) and Lua 5.4.7 (famous, 698). Results and
the contamination comparison: `oaustegard/experiments` `swarm-decomp/README.md`. Kind: **P**
prevented in code, **D** detected by a named signal, **W** warned in the runbook.

## Effort rungs on the decompilation tail

Dollars per function flipped, by the rung of the worker whose gate flipped it, both targets:
default $0.039 (696 flips, 993 workers), `high` $0.198 (253, 622), `high` feature $0.579
(135, 342), `xhigh` $1.30 (31, 296), `max` $3.90 (20, 214). Each rung only saw what the
rungs below left, so these are marginal prices, not the same task at five efforts. The
neat* tail Haiku `max` could not clear: 274 functions, median 111 instructions, 268 with a
loop; solve rate by size fell from 100% under 16 instructions to 0 of 34 at 384 or more.
Final: neat* 796/1,070, Lua 679/698, $281.13 of worker spend, 2,489 workers, 862 merges.
